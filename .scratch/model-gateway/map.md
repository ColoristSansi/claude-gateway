# 本地模型网关（Claude Gateway）— wayfinder map

Type: wayfinder:map
Status: done (2026-10-15)

## Destination

一份可据以实施的技术选型与架构设计（模块划分、接口契约、三个客户端的接入方案、实施顺序），外加一个**最小可运行原型**：Claude Desktop 在 3P 模式下走本网关流式问答正常、四个家族名（claude-fable / claude-opus / claude-sonnet / claude-haiku）映射生效。

## Notes

- 全程中文。用户不写代码，实现由 AI 完成；用户只做决策与验收。
- 与用户交流一律用弹窗（`ask_user_question`），不要用长段落文字提问。
- 计划为主（wayfinder 默认），但本 effort 经用户明确覆盖，**包含「最小可运行原型」的执行**。
- 目标机器：Windows 单机，仅本机单用户（127.0.0.1 回环），本机没有 Docker。
- 已确认技术栈：Tauri 2 + Rust 核心 + React 前端 + 系统托盘；SQLite 存配置与日志；密钥用 Windows DPAPI。
- 上游协议策略：优先 Anthropic 原生直通，缺失时降级 OpenAI Chat；**协议记在虚拟模型上，不在供应商上**（同一供应商不同协议支持的模型不同）。
- 每会话最多解析一张票据；**research 票据例外，可批量解析**。HITL 票据必须真的与用户对话，不得自问自答。
- 调研产物在 `.scratch/model-gateway/research/`（已归档的在 `research/archive/`），克隆的参考仓库在 `.scratch/model-gateway/vendor/`（体积大，将来建仓时要写进 `.gitignore`）。
- 术语以仓库根 `GLOSSARY.md` 为准：请求目标一律叫**上游**，不要引入近义词。

## Decisions so far

### 调研（已解析）

- [三个客户端的接入硬约束](issues/01-research-client-integration.md): Claude Desktop 3P 是官方功能（`inferenceProvider=gateway`，配置在 `%LOCALAPPDATA%\Claude-3p\configLibrary\`）；Claude Code 只要 `/v1/messages` + SSE 保序 + `ping` 转发；Codex 的 `wire_api` 官方唯一合法值是 `responses`。
- [供应商 API 契约与 models.dev](issues/02-research-provider-apis.md): 四家供应商都提供 Anthropic 端点，但路径契约各不相同（千问不能带 `/v1` 且无 `/v1/models`）；models.dev 的 `npm` 字段只能当预设先验。
- [同类网关的实现](issues/03-research-similar-gateways.md): cc-switch(MIT) 的「只改关键字段」写入引擎与安全 route id 可直接借鉴；CodexPlusPlus 是 AGPL，只能借思路。
- [四个参考程序的协议转换实现](issues/04-research-reverse-proxies.md): 四家一致走中间表示、不做两两直转；三条 Anthropic 入站；四条可直接抄的流式细节。
- [自研还是二次封装](issues/05-research-build-vs-wrap.md): 结论是**自研薄转换层**，五个候选全部出局（LiteLLM 形态错配且钉 proprietary 包、new-api 是 AGPL+附加条款、one-api 停滞、claude-code-router 的转换主体不在其仓库而在外部包、AIClient-2-API 是 GPL）；其中「外部包」那一条已由票据 21 更正为形态与保真缺口。
- [ccr 的转换层是不是黑盒](issues/21-research-ccr-gateway-package-source.md): 不是——`@the-next-ai/ai-gateway` 有公开 MIT 源码且与 npm 1.0.21 版本对齐（误判根源是它没有 `repository` 字段）；ADR-0001 的出局理由已从「黑盒」改为形态与保真缺口，结论不变，该包升级为协议编解码的一手移植参照。
- [未登录态下能否只用网关凭据](issues/24-research-client-login-state.md): **「未登录」对三个客户端都不是阻断性错误**（Claude Code 零凭据就能完成 onboarding；Codex CLI 自定义 provider + `env_key` 免登录；Desktop 3P 官方允许占位 key）。两条写入硬约束：Claude Code **只写 `ANTHROPIC_AUTH_TOKEN`**（`ANTHROPIC_API_KEY` 需交互批准、曾拒绝即静默失灵），Codex **不写 `requires_openai_auth = true`** 且 `env_key` 声明的变量必须真存在。唯一例外是 **Codex 桌面应用的模型选择器按登录身份门控**（官方 not planned）→ 新开 [Codex 卡片：CLI 与桌面应用要不要拆开](issues/25-grilling-codex-desktop-card-split.md)。**（该「例外」已由票 25 实测定案推翻：选择器不按登录门控，只看有没有模型目录文件。）**
- [Ollama 入站（`/api/chat`、`/api/tags`）的形状与映射](issues/34-research-ollama-inbound.md): **NDJSON 一行一帧，不是 SSE**（末帧 `done:true` 才是终态，统计字段与可能缺失的 `done_reason` 都在帧顶层，`stream` 缺省 true）；`message.content` 是字符串、`tool_calls[].arguments` 是**对象** → Ollama 面必须**缓冲工具调用到 block stop**；回传只有 `tool_name` → 入站要**按名反查补 `tool_use_id`**，否则 Anthropic 出站 400；错误体是 `{"error":"…"}` 不是 OpenAI 信封；`/api/tags` 与 `/v1/models` 同一集合（`digest` 用名字的 sha256、不谎报 gguf）；`/v1/chat/completions` **不是第二个 Ollama 面**。spec §4.4 已铺开，两处待决长成票 36 / 37。

### 设计决策（已定）

- [终点与范围](issues/08-design-destination-and-scope.md): 设计文档 + 最小原型；三个客户端全要；本机单用户；SQLite + DPAPI；用量统计、请求日志、models.dev 半自动配置、上游模型自动发现都要；**不做多上游自动切换**。
- [协议策略与声明式供应商表](issues/09-design-protocol-and-provider-table.md): Anthropic 优先、OpenAI Chat 兜底；协议随虚拟模型走；供应商差异做成声明式表（照 new-api `advancedcustom` 的形状）。
- [模型暴露与客户端配置](issues/10-design-model-exposure-and-client-config.md): 全局四个家族槽位 + 每客户端可覆盖；配置自动写入 + 首写备份 + 幂等重写 + 一键还原；Claude Desktop 另做 1P/3P 一键切换；入站加 Ollama 兼容。
- [技术栈、存储与可观测](issues/11-design-stack-storage-and-observability.md): Tauri 2 + Rust + React + 托盘；SQLite + DPAPI；日志默认只记元数据、body 可临时开启、保留 7 天；六项保真能力全要。
- [ccr / ai-gateway 的角色](issues/22-grilling-reconsider-ccr-gateway-core.md): 源码公开后**维持自研**，不引入 Node sidecar；`@the-next-ai/ai-gateway`（MIT）作为协议编解码的一手移植参照，并已修正「黑盒」的措辞归属。
- [协议转换的测试与回归策略](issues/19-grilling-test-strategy.md): **三层网**（Rust 单测 / 黄金 fixture 回放 / 真实客户端半自动冒烟）；**结构级断言 + 字段级掩码**取代现有子串断言；fixture = 原始 SSE 字节 + `meta.json` 的**按字节偏移切块方案**（一个 fixture 派生整帧 / 半帧 / 单字节流 / CRLF 多种切法）；mock 加**请求回显**（否则头类 quirk 测不了）；`quirk::all()` **双向守卫**（枚举值 ⇄ fixture 标签）；**单一入口** `check.ps1`（`-Quick` / `-Replay` / `-Live` / `-Smoke`，默认全跑）取代 `verify.ps1`（退役删除）、真实上游验证降级为 `#[ignore]` 手动；另纳入并发会话隔离、首帧延迟不变式、日志脱敏、配置写入引擎断言、模型解析四边界；`count_tokens` 与非流式写进**待覆盖清单**（实现见票 26，排在铺套件之前）。套件自己的验收标准写在票内（7 条）。
- [前端信息架构与交互](issues/17-grilling-ui-information-architecture.md): 导航保持 7 页；主路径由**概览页三步清单**串起（首启不另做向导）；上游四步向导（选供应商与拉模型可跳过、自检强制）；槽位表四行 + 非流式 `max_tokens:1` 探针自检 + 客户端标签做覆盖；客户端卡片**四态且每次进页面实读文件比对**（Desktop 改完须完全退出重启）；日志详情四段、body 开关 1 小时自动关；错误统一模板 + 脱敏诊断包；概览两个一键动作（批量切换、haiku 槽位端到端验收）；网关未运行时常驻横幅、换端口须用户确认并自动同步已生效客户端的地址。
- [打包、自启动、升级与首启引导](issues/18-grilling-packaging-and-updates.md): NSIS **per-user** 安装包（装 `%LOCALAPPDATA%`、不需管理员）+ 免安装 zip（官方无 portable bundle，手工打包，不参与自动更新）；**不签名**；关窗**隐藏到托盘**、只有托盘「退出」才停，**开机自启默认关闭**（开启时写 HKCU Run，避开卸载残留）；升级走**公开 GitHub Releases + 应用内检查**（https 与签名校验都强制），用户确认后 passive 静默安装并自动重启，**升级不改端口/数据/客户端配置**，数据目录另留一份上一版包并给回退指引；数据目录 `%APPDATA%\com.claudegateway.desktop\`（安装版与 zip 版共用，设置页只读路径 + 打开目录，不提供搬家）；卸载默认**保留数据**（原生「Delete app data」勾选），并弹一次「还原客户端配置 / 保持现状」（默认还原）；首启不另做向导，客户端页卡片做安装检测（「未登录」不阻断，票 24）。
- [供应商表：认证与可用 wire 的粒度](issues/23-design-provider-table-granularity.md): **认证按「上游 × wire」各存一份**（未填继承上游默认；opencode Go 同一把 key 打 Chat 面 200、打 Anthropic 面 401，一上游一凭据不成立；不拆上游实体、不建独立凭据表）；**可用 wire 按「(上游, 真实模型)」一条目录记录**存 `supported_wires`（三值 `anthropic` / `openai-chat` / `openai-responses`）+ `source`（`manual`/`upstream`/`doc`），**空集 = 未声明是正常态**；**虚拟模型引用目录条目**再选 wire（ID 打错字因此不会被静默放行）；校验三层——配置期主拦（只许选声明过的值，未声明可手选并标注）+ 请求期早拒 400 兜底 + 自检为准；票 17 挂起的「协议列能否表内手改」结案为**可改但只限声明的值**；旧 quirk `ClaudeModelsOnAnthropicOnly` **删除**（票 19 的双向守卫与负例 3 同步改判据）；灌入靠上游向导「拉模型」抓一次存库、可手动重拉，上游报的端点路径经 `pathTemplates` 反查成 wire（查不到就忽略 + 记警告），优先级 **手改(锁定) > 上游 `/v1/models` > 随包内置文档表 > 未声明**，models.dev 不参与 wire 判定；实测 commandcode 89/89 带 `supported_endpoints`（路径数组，70/89 多值），opencode 两面 `/models` 都不报端点且 Anthropic 面 `/models` 404 → 它的逐模型 wire 只能靠内置文档表 + 手工。**已归档为 [ADR-0004](../../docs/adr/0004-provider-table-granularity.md)**（票 27 的测试策略 ADR 顺延为 0005）。
- [Codex 卡片：CLI 与桌面应用要不要拆开](issues/25-grilling-codex-desktop-card-split.md): **不拆卡**——三次本机实测推翻了前提：**桌面应用的模型选择器不按登录门控**，写上 `model_catalog_json` 模型目录后，「Codex」与「ChatGPT Work」两个模式都能看到网关模型（全程零官方登录）；mock 实测应用确实按 `config.toml` 的 provider 发 `POST /v1/responses`（要 SSE，票 24 的 U5 结案）。客户端页保持票 17 的**一张 Codex 卡 + 四态徽章**；「未登录」不做警告，桌面应用独有的限制只有**云线程需要官方登录**（普通说明 + 一个只做跳转的登录引导按钮）；**绝不触碰 `auth.json`**。新开 [Codex 模型目录：内容、并存与还原](issues/31-grilling-codex-model-catalog.md)（网关必须生成目录文件）与 [原型：Codex 端到端](issues/32-prototype-codex-e2e.md)。
- [配置写入引擎的事务性](issues/28-grilling-config-writer-transactionality.md): **21 条定案**——引擎 = 显式**接管键清单**（floor）+ 按格式保序改写 + 解析失败即停，唯一真相在 SQLite `client_config_state`（上次写入的接管键值/时间/备份路径/首写是否存在）；写入 = 同目录临时文件 + fsync + 原子替换（`ReplaceFileW`，失败退 `rename`，最多 3 轮），被占用/权限失败退避重试 3 次后报错给路径；**冲突只针对接管键**（非接管键变化、别的程序写自己的段都不算），冲突 = 放弃 + 提示，记录缺失按首次接管；**接管键以网关为准覆盖**，非接管键保留（票 19 断言③的「手改字段」按非接管键理解）；幂等 = 语义相同就不写（mtime 不变）、要写则字节稳定；还原默认**摘键**（Desktop 还要摘 `_meta.json` 的 entries/appliedId，不动别的 profile）、可选**整份回滚**（仅当文件未被外部改过）、网关新建且只含网关内容的文件整个删；备份在 `%APPDATA%\com.claudegateway.desktop\backups\<客户端>\`，首写快照常驻 + 滚动 5 份/90 天，首写时文件不存在只记 marker；多文件按依赖顺序逐个原子替换（先被引用者后指针），**不移植跨文件 pending 事务**；单实例互斥量 + 每文件一把锁，不做跨进程锁文件；写入/还原记库 + 元数据日志，不新做历史页。spec §8 规则已按此改写并新增 §8.4；术语表新增接管键/首写快照/摘键还原/整份回滚/外部改动；**已归档为 [ADR-0006](../../docs/adr/0006-config-writer-owned-keys.md)**。**现有 `desktop-3p.ps1` 三处被推翻**（profile 整份重建、`standard` 不维护 `_meta.json`、`restore` 删整个 configLibrary），属实现面。
- [实现 `count_tokens` 与非流式入站](issues/26-grilling-count-tokens-and-non-streaming.md): **入站契约补齐**——`count_tokens` 在 `wire=anthropic` 时转发上游 `<path_anthropic>/count_tokens`（形状 = `/v1/messages` 去掉 `max_tokens`/`stream`），**非 2xx / 连不上 / 10 秒超时 / 响应缺 `input_tokens` 全部降级本地估算**（端点永不失败）；本地估算 = system + tools + messages 全算、ASCII 4 字符/token、非 ASCII 每字符 1 token、`data`（base64）不计、图片常量 1500。**非流式 `/v1/messages` 出站仍是 `stream:true`**，网关把 IR 流缓冲到终态再组装完整 message（`content` 恒为数组；**没有 signature 的 thinking 块丢弃**；上游断流/无终态 → 502 JSON）；`max_tokens:1` 探针**不短路**、照常走上游；**统一上游超时不加**，只给探针档（`max_tokens <= 16`）加 **20 秒**上限（超时 504）——实测 commandcode 的 Chat wire + deepseek 在 `max_tokens:1` **直连 curl 也挂住**。**顺带更正票 16**：`provider: gateway` 的连接测试只打非流式 `/v1/messages`（`max_tokens:1`，只看状态码），`count_tokens` 的唯一调用点是 Azure Foundry provider、SDK 的 `countTokens()` 零调用点。原型已实现并实测（`cargo test` 9/9、`verify.ps1` 10/10、两 wire 非流式与两条 count_tokens 路径都验过）。
- [Codex 模型目录：内容、并存与还原](issues/31-grilling-codex-model-catalog.md): **8 条定案**——目录只装网关暴露的虚拟模型（四家族名 + 普通虚拟模型 + Codex 覆盖名）；**不抄官方条目**（网关模式下 `model_provider` 指向网关，官方条目留着也会被发到网关；摘键还原后自然回来，票 32 可实测复核）；文件 `<CODEX_HOME>/claudegateway-model-catalog.json` + **相对文件名**指针；还原 = 摘指针 + 仅当内容与网关最后写入逐字节一致才删文件 + 备份保留；行字段沿用模板默认（`visibility=list`、窗口 262144），不做用户可配；**模板按出站协议分**（`anthropic` → cc-switch 中性模板 `shell_command`、无 freeform apply_patch；`openai-chat` → 经典 gpt-5.5 模板）；`model_catalog_json` 是接管键，冲突即放弃并提示 + 另给显式「认领并覆盖」；写前自检（可解析 / 非空 / 至少一条 `list` / `slug` 非空唯一 / 解析必需字段齐）不过就不写，还原时兜底；顺序固定（四家族名在前，普通模型按名排），顶层 `model` 归票 32；写完只提示「完全退出重启 Codex」，不杀进程。事实：本机 `codex debug models` 与 `--bundled` 逐字节一致（11 条，8 `list` / 3 `hide`，658,608 字节）；解析必需字段 = `slug` + `base_instructions`（或 `model_messages.instructions_template`）+ `supports_reasoning_summaries` + `supports_parallel_tool_calls`。spec §7 已按此改写，术语表加「Codex 模型目录」。
- [模型自动发现的失败与空结果怎么降级](issues/35-grilling-model-discovery-fallback.md): **九条定案**——wire 反查警告落进上游记录的「上次拉取警告」+ 卡片/列表角标（下次成功拉取清除，不阻断保存、不进概览「最近错误」）；**404/405 与「200 但零条」= 该上游不提供模型发现**（软提示 + 手填入口，不报红），其他非 2xx/超时/断网 = 失败（失败提示里直接给「手工添加模型」，向导内联新增，`manual` 锁定，上游仍可保存）；**重拉失败保留旧条目**，只有成功才覆盖 `upstream` 来源的条目；拉取用上游 `default` 凭据、不为每个 wire 面重复拉；拉取 **20 秒超时、不自动重试**（失败提示里给「重试」按钮）；这两类提示**不计入**侧栏「未通过自检的上游数」与概览三步就绪（判据只看自检）；**opencode 只拉带凭据那份**——19/85 的尾巴已探明是**权限过滤**（一个全量目录按 key/工作区启用集**原位过滤**：严格子集 + 顺序保留、字段集合一致且无任何权限元数据、`created` 随请求时刻变），**只在无凭据那份里的 66 条带 key 调用一律 403 `Model access is disabled`**（三协议一致），Go 面（`/inference/go/v1` 与 `/zen/go/v1` 字节一致）37 条与凭据无关、`x-opencode-session` 只影响 go 的 chat → 票 23 的「两份合并」就此收窄为「带凭据拉取 404/空结果才退匿名」。spec §6/§9/§10 与 GLOSSARY（加「模型发现」）已回写，票 17 追加 §12。**本票不留新票，无新雾。**
